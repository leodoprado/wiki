`SOLID` é um conceito de cinco princípios de design orientado a a objetos que orientam a construção de softwares mais organizados, flexíveis, reutilizáveis e fáceis de manter.

Seu principal objetivo é reduzir o acoplamento entre classes, facilitar a evolução do sistema e tornar o código mais simples de entender, testar e modificar, minimizando o impacto de mudanças e favorecendo boas práticas de desenvolvimento.

Em resumo, `SOLID` é uma base para escrever código de qualidade, tornando aplicações mais escaláveis, legíveis e preparadas para futuras alterações.

# 2. Resumo

|Letra|Nome|Ideia principal|
|---|---|---|
|**S**|**Single Responsibility Principle**|Uma classe deve ter apenas uma responsabilidade.|
|**O**|**Open/Closed Principle**|Estenda o comportamento sem modificar código existente.|
|**L**|**Liskov Substitution Principle**|Classes filhas devem substituir a classe pai sem quebrar o sistema.|
|**I**|**Interface Segregation Principle**|Prefira interfaces pequenas e específicas.|
|**D**|**Dependency Inversion Principle**|Dependa de abstrações (interfaces), não de implementações concretas.|

- **S** → Cada classe faz **uma única coisa**.
- **O** → Novas funcionalidades são adicionadas **sem mexer no que já funciona**.
- **L** → Uma classe derivada pode ser usada **no lugar da classe base** sem causar erros.
- **I** → Cada classe implementa **apenas as interfaces de que realmente precisa**.
- **D** → As classes se comunicam por **interfaces**, reduzindo o acoplamento.
