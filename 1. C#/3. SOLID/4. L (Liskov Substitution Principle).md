```
Uma classe filha deve poder substituir sua classe pai sem quabrar o funcionamento do programa.
```

Se uma classe herda outra, ela deve respeitar o comportamento esperado da classe base.

#### ❌ Exemplo ruim
```
public abstract class Pagamento
{
    public abstract void Processar(decimal valor);

    public abstract void Cancelar();
}

public class CartaoCredito : Pagamento
{
    public override void Processar(decimal valor)
    {
        Console.WriteLine("Pagamento realizado no cartão.");
    }

    public override void Cancelar()
    {
        Console.WriteLine("Estorno realizado.");
    }
}

public class Pix : Pagamento
{
    public override void Processar(decimal valor)
    {
        Console.WriteLine("Pagamento via PIX.");
    }
    
    public override void Cancelar()
    {
        throw new NotSupportedException("PIX não pode ser cancelado.");
    }
}

CancelarPagamento(new CartaoCredito()); // Funciona
CancelarPagamento(new Pix()); // ERRO
```
Pix NÃO pode substituir Pagamento sem alterar o comportamento esperado.

#### ✅ Exemplo bom
Ao invés de assumir que todo pagamento pode ser cancelado, modelamos isso corretamente.
```
public interface IPagamento
{
    void Processar(decimal valor);
}

public interface ICancelavel
{
    void Cancelar();
}

public class CartaoCredito : IPagamento, ICancelavel
{
    public void Processar(decimal valor)
    {
        Console.WriteLine("Pagamento no cartão.");
    }

    public void Cancelar()
    {
        Console.WriteLine("Estorno realizado.");
    }
}

public class Pix : IPagamento
{
    public void Processar(decimal valor)
    {
        Console.WriteLine("Pagamento via PIX.");
    }
}
```

- No exemplo ruim, o erro só aparece **em tempo de execução**.
- No exemplo bom, o compilador já impede o uso incorreto.
